This recipe generates synthetic data with a formal differential privacy
guarantee. You fit a DP snapshot from a real table, then generate against an
enforced budget ceiling. For the concepts behind it, see
[Differential privacy in Decoy](/docs/concepts/differential-privacy).

## 1. Prepare your source data

Start with a CSV you want to generate from:

```csv
patient_id,age,diagnosis_code,readmitted
1,45,I10,0
2,67,E11,1
3,52,J44,0
```

## 2. Fit a differentially private snapshot

`decoy fit --epsilon` releases a `dps-marginal/v3` artifact instead of the
exact snapshot. Select DP mode with `--epsilon`, pass the required `--delta`,
and declare every column as a typed carrier:

```console
$ decoy fit patients.csv --output patients.snapshot.json \
    --epsilon 1.0 --delta 1e-6 \
    --dp-number age:0:120 \
    --dp-text diagnosis_code \
    --dp-flag readmitted
OK patients.snapshot.json
  dps-marginal/v3; epsilon_total=1.0, delta_total=1e-6
```

Carrier flags:

- `--dp-number COL:LO:HI` declares a numeric column and its **data-independent**
  domain. You supply `LO:HI`; the engine does not read the real min and max,
  because that would leak at zero budget. Values outside the domain clamp to
  the bounds.
- `--dp-text COL` declares a categorical string column. Rare categories drop
  under a noisy threshold.
- `--dp-flag COL` declares a boolean column.

Every source column must get a carrier, or the fit refuses. Pass
`--dp-allow-omit` to deliberately leave a column out of the release.
`--epsilon` is incompatible with `--parse-dates` and `--joint`.

## 3. Declare the budget ceiling and generate

In the pipeline, `global_settings.dp` sets the enforced `(epsilon, delta)`
ceiling for the generated output. It holds only those two keys. Sample the
snapshot with `type: statistical` columns:

```yaml
version: 1

global_settings:
  seed: 42
  dp:
    epsilon: 1.0
    delta: 1e-6

sources: {}

tables:
  - name: patients
    row_count: 1000
    generate_columns:
      - name: patient_id
        type: sequence
        start: 10000
      - name: age
        type: statistical
        snapshot_file: ./patients.snapshot.json
        source_column: age
      - name: diagnosis_code
        type: statistical
        snapshot_file: ./patients.snapshot.json
        source_column: diagnosis_code
      - name: readmitted
        type: statistical
        snapshot_file: ./patients.snapshot.json
        source_column: readmitted

targets:
  patients:
    type: file
    format: csv
    path: ./patients_synthetic.csv
```

Decisions that matter:

- **`epsilon: 1.0`** is a common middle choice: moderate privacy, usable
  fidelity. Start here and adjust.
- **`delta: 1e-6`** is the failure probability. Keep it a small positive number
  below 1, typically below 1/n for n rows.
- The ceiling must cover the fit's spend. If the DP releases a pipeline
  consumes compose to more than this, the compile fails (step 4).

## 4. Validate and run

```console
$ decoy validate config pipeline.yaml
OK pipeline.yaml

$ decoy run pipeline.yaml --mode generate
╭─ decoy run ──────────────────────────────────────────────────────────────────╮
│ Pipeline  pipeline.yaml                                                      │
│ Mode      generate                                                           │
│ Rows      1000                                                               │
│ Elapsed   3.24s                                                              │
╰──────────────────────────────────────────────────────────────────────────────╯
```

The output is 1,000 rows of synthetic data sampled from the noisy snapshot. If
the composed spend of the DP releases exceeds the declared ceiling, the compile
fails with `dp_budget_exceeded` before any row is written.

## 5. Inspect the output

```console
$ head -4 patients_synthetic.csv
patient_id,age,diagnosis_code,readmitted
10000,42,I10,0
10001,71,E11,1
10002,49,J44,0
```

## 6. Measure utility and adjust

Check whether the synthetic data is useful for your downstream task, and
compare key statistics against the source. Under DP the counts carry noise, so
expect the marginals to track the source approximately rather than exactly: a
column's mean and category frequencies land near the source values, not on
them.

If fidelity is too low you can:

- **Raise epsilon** (weaker privacy, better fidelity): try 2.0 or 3.0.
- **Raise delta** (higher failure probability, better fidelity): try 1e-5, and
  accept the higher risk.
- **Release fewer columns**, or **narrow a numeric domain** so each bin covers
  less range.

## 7. How the budget composes

The requested `(epsilon, delta)` is the budget for the **whole fit**, covering
every declared column together. The fit allocates its internal queries (one row
count, one per numeric column, two per categorical column) and composes them so
the total spend stays within the epsilon you asked for. You do not pay a
separate epsilon per column, and there is no `(k + 1) * epsilon` growth.

What composes across a pipeline is distinct **releases**. Each `decoy fit`
mints one release. When a pipeline draws statistical columns from several
independent DP fits, their budgets add up and are checked against the
`global_settings.dp` ceiling. Columns sharing one release are charged once. So
to stay under a total budget, plan the epsilon of each independent fit, not a
per-column figure.

## 8. Constraints and limitations

- **Three carriers only.** Numeric (`--dp-number`), categorical text
  (`--dp-text`), and boolean (`--dp-flag`). Dates and free text are not
  eligible; generate them with non-DP types outside this mechanism.
- **No conditional or joint generation.** `condition_on` and `--joint` are
  rejected under DP. All DP columns are released as independent marginals.
- **Domains are declared, not inferred.** You pass each numeric column's
  `LO:HI`. The engine does not read it from the data.
- **The ceiling is enforced.** If the composed spend exceeds the declared
  `(epsilon, delta)`, the pipeline fails to compile.
