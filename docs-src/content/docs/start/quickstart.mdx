---
title: Mask your first CSV
description: Scan one CSV, review its pipeline, validate the run, and verify the masked output.
---

This tutorial uses the complete Decoy workflow on one small file. It assumes
that Decoy is installed. See [Install](/docs/start/install) if the `decoy`
command is not available.

## 1. Create a source file

Save this file as `customers.csv`:

```csv
customer_id,name,email,status
C001,Ada Lovelace,ada@example.com,active
C002,Alan Turing,alan@example.com,closed
```

## 2. Scan the data

```bash
decoy pre-scan customers.csv --show-fields
```

Review the possible sensitive fields. A scan is a suggestion. You decide
which fields require masking.

## 3. Create a pipeline

```bash
decoy init customers.csv --output pipeline.yaml
```

This command scans the file and creates a column-aware pipeline. The file
contains a `# REVIEW:` comment for each suggested strategy.

Open `pipeline.yaml`. Make sure that the source and target paths are correct.
Then review every column rule. Do not run an unreviewed suggestion against real
data.

For this tutorial, use these column rules:

```yaml
tables:
  - name: data
    columns:
      - name: customer_id
        strategy: hash
        namespace: customer_identity
      - name: name
        strategy: faker
        provider: person_full_name
      - name: email
        strategy: faker
        provider: person_email
      - name: status
        strategy: passthrough
```

## 4. Validate the pipeline

```bash
decoy validate pipeline.yaml
```

Validation runs the configuration, compile, and local preflight checks. It
checks that the source is readable and reports target overwrite risk.

If you want to inspect the compiled work, run:

```bash
decoy validate compile pipeline.yaml --explain
```

## 5. Run the pipeline

```bash
decoy run pipeline.yaml --evidence-out evidence.json
```

Open the target CSV from `pipeline.yaml`. The identifiers, names, and email
addresses now contain masked values. The `status` values remain unchanged.

## 6. Verify the output

Check for residual sensitive data, relationship failures, and policy findings:

```bash
decoy post-scan integrity output.csv \
  --source customers.csv --config pipeline.yaml --output integrity.json
```

Replace `output.csv` with the target path from your pipeline.

Measure how much the output distribution changed:

```bash
decoy post-scan fidelity customers.csv output.csv \
  --config pipeline.yaml --mode warn --report-out distribution.json
```

Then make sure that the evidence manifest still matches the files:

```bash
decoy report verify evidence.json
```

Distribution integrity measures utility. Evidence verification detects file
drift. Neither check certifies that the output is safe to publish.
