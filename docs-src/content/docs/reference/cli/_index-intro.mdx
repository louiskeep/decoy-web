## Exit codes

`decoy` uses its exit code to carry outcome, not just pass or fail, so scripts and
CI pipelines can branch on it without parsing output.

| Code | Meaning |
| --- | --- |
| `0` | OK. The command completed successfully. |
| `1` | Usage error. Bad arguments, a malformed config, or similar. |
| `2` | Deprecated-invocation or warning-gate exit. The legacy `forge` console command exits `2` without running anything, printing a message to invoke `decoy` instead; `decoy validate config --fail-on-warning` and `decoy preflight --fail-on-warning` also exit `2` when an advisory warning fires (for example an output target that already exists). |
| `3` | Runtime error. The command started but failed while running. |
| `4` | Findings. The command completed but surfaced something that needs review, for example a scan finding PII, or a distribution-fidelity check landing below policy (`decoy report fidelity --mode fail` also uses `4` for its own warning/fail verdicts). |

Exit code `2` is narrower than the findings split above: it covers the
legacy `forge` shim, which exits `2` without running anything, plus the
`--fail-on-warning` gate on `validate config` and `preflight`.

See [Use decoy in CI](/docs/how-to/use-decoy-in-ci) for how to branch on these
codes in a pipeline, including why exit code `4` is not the same as a failure.
