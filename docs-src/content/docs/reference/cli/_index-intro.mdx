## Exit codes

`decoy` uses its exit code to carry outcome, not just pass or fail, so scripts and
CI pipelines can branch on it without parsing output.

| Code | Meaning |
| --- | --- |
| `0` | OK. The command completed successfully. |
| `1` | Usage error. Bad arguments, a malformed config, or similar. |
| `2` | Deprecated invocation or warning-gate exit. The legacy `forge` command exits `2`. `decoy validate config --fail-on-warning` and `decoy validate preflight --fail-on-warning` also use this code. |
| `3` | Runtime error. The command started but failed while running. |
| `4` | Findings. The command completed but found something to review. Examples include scan findings, failed integrity checks, and fidelity below policy. |

Renamed commands can print a migration warning and still exit `0` when the
underlying command succeeds. Exit code `2` covers the legacy `forge` shim and
the `--fail-on-warning` validation gate.

See [Use decoy in CI](/docs/cli/automation/use-decoy-in-ci) for how to branch on these
codes in a pipeline, including why exit code `4` is not the same as a failure.
