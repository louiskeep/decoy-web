Guides

Scan for PII

Profile a dataset with STORM, review what it found, and turn the findings into an explicit masking pipeline.

STORM profiles a dataset before you write a masking pipeline: what fields look like PII, which columns form a quasi-identifier group together, and a re-identification risk score. It never masks anything and never applies a pipeline on your behalf; it surfaces candidates for you to review. Run against decoy CLI 0.1.0; every command block below is real output.

Suggestions, not classification

STORM's detectors are heuristics. A finding is a candidate, not a verdict: you read it, decide which mask strategy fits, and write that decision into the YAML as an explicit strategy: entry. Nothing is masked until you do.

1. Scan the file

--rows N --strategy random caps and samples large files instead of scanning everything; --json prints the full profile to stdout for piping into other tooling.

storm scan is deprecated

decoy storm scan is the old name for this command. It still works today (it prints a migration warning on stderr and runs analyze underneath) but is deprecated. Use decoy storm analyze.

2. Review the findings

Drill into one field for its top values and detector detail:

--pii high --quasi on storm fields narrows the list to fields that are both high-PII and part of a quasi-identifier group, and --json pipes just the matching field names to something like jq.

4. Check the result caught everything you meant to mask

decoy storm integrity runs the same post-mask checks the platform runs when run_storm: true is set: residual PII, foreign-key preservation, and policy validation against the config. Point it at the masked output and its pre-mask source:

Two fail findings, exit code 4: the scaffolded strategies above (truncate on customer_id, redact on names) still left something the detector considers PII. That is the point of running this check, not a bug in the recipe; the report names the exact column and detector so you know which # REVIEW: line to revisit. It exits 0 when nothing is flagged and EXIT_FINDINGS (4) whenever a column still carries real values through. See use Decoy in CI for wiring that exit code into a build gate, and STORM for why detection and masking stay two separate, inspectable steps.
