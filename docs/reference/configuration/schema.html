Configuration schema

The complete field-by-field pipeline schema, for editor validation.

decoy schema prints the full JSON Schema for a pipeline config (PipelineConfig), generated from the same Pydantic models decoy validate config and decoy run validate against, not hand-maintained separately. Point an editor's YAML/JSON Schema support at it for autocomplete and inline validation, or read the collapsed reference below.

Regenerate it any time; this page is a snapshot from decoy 0.1.0 / decoy-engine 0.4.0 and can drift from a newer install. decoy schema is the source of truth, not this page.

Top-level shape

A pipeline config (PipelineConfig) has these top-level keys:

KeyRequiredTypeWhat it is
versionyes1 (const)Schema version. Currently always 1.
global_settingsyesGlobalSettingsSeed, mask secret reference, and pipeline-wide policy knobs.
sourcesnomap of name to sourcetype: file, s3, or gcs (discriminated on type). See connectors.
tablesyeslist of TableConfigOne entry per mask or generate table. At least one required.
relationshipsnolist of RelationshipConfigForeign-key edges between tables (parent, children, orphan policy).
targetsyesmap of name to targettype: file, s3, or gcs. At least one required.
namespacesnomap of name to NamespaceConfigExplicit namespace declarations, mostly informational; most namespaces are declared implicitly by column config.
run_stormnoboolean, default falseRun a STORM scan as part of this pipeline.
validatorsnolist of ValidatorEntryPost-run checks: luhn, fk_intact, leak_check, regex_match, and others.
quarantinenoQuarantineConfig or nullRoute rows that fail a wired trigger to a side file instead of failing the run.
subsetnoSubsetConfig or nullFK-aware referential subsetting (decoy subset).

Every object in this schema has additionalProperties: false: an unrecognized key fails decoy validate config rather than being silently dropped, this is what makes a typo'd field name a validation error instead of a quiet no-op.

Key nested objects

ColumnConfig (tables[].columns[]): one mask column. Required: name, strategy. Everything else, provider, namespace, cardinality_mode, deterministic, scale, provider_config, vault, allow_collisions, and more, is optional and strategy-dependent. See strategy before/after for real examples.

GenerateColumnConfig (tables[].generate_columns[]): one synthesis column. Required: name, type (one of faker, sequence, categorical, formula, reference, statistical, derived, derived_aggregate, grouped_series, windowed_date, group_key). Per-type parameters ride flat on the same object (extra: allow), not nested under a config: key.

RelationshipConfig (relationships[]): one FK edge. parent and each entry in children are a RelationshipEnd (table + columns, columns supports composite keys). orphan_policy is required: one of preserve, remap, warn, fail.

TableConfig (tables[]): a table is either a mask table (columns, fed by a sources entry) or a generate table (generate_columns + row_count, no source), not both. transforms is an ordered list of shaping ops (filter, sort, limit, dedupe, derive, drop_column), each discriminated on its own op field.

GlobalSettings: seed is the only required field. mask_secret_ref is a reference (env:NAME or file:/path), never the secret itself, see keys and the vault.
