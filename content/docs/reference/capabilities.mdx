## Masking strategies (24)

Replace sensitive values while preserving row alignment and (when configured) referential integrity across tables.

| Strategy | Input → Output | Use case |
|---|---|---|
| `faker` | real → synthetic (provider) | Names, emails, addresses |
| `hash` | real → 16-char hex digest | Deterministic anonymization |
| `fpe` | real → in-charset masking | Preserve format (credit cards, SSNs) |
| `redact` | real → fixed placeholder | Remove completely (ssn → `[REDACTED]`) |
| `passthrough` | real → unchanged | Publicly safe columns |
| `date_shift` | real → offset date | Temporal distance preserved; optionally group-anchored per entity |
| `windowed_date` | real → random in year | Preserve calendar properties |
| `truncate` | real → prefix | Keep first N chars (postcode → `900`) |
| `bucketize` | real → range label | Age 45 → `[40-50)` |
| `bucket_perturb` | real → adjacent bucket | Bounded perturbation (age 45 → 48) |
| `categorical` | real → random category | Uniform or weighted sampling |
| `shuffle` | real → shuffled column | Break row identity, preserve marginal |
| `geo_generalize` | real → generalized coords | Lat/long → km-grid cell |
| `joint_mask` | real + context → masked + joined | Preserve value pairs (city + country) |
| `code_set` | real → valid code | Medical codes with chapter-preservation option |
| `text_redact` | real → redacted (pattern + NER) | Find and redact PII in free text |
| `text_mask` | real → redacted + replaced | Redact and replace with synthetic text |
| `formula` | real + siblings → computed | Hash, concat, truncate (DSL-driven) |
| `derived` | real + siblings → evaluated | Lark-grammar expressions with slicing, concat |
| `derived_aggregate` | real + siblings → aggregated | Sum, count, mode across rows |
| `group_key` | real + context → grouped | Deterministic per-group value |
| `grouped_series` | real + sequence → offset series | Offset a sequence per group (order IDs) |
| `top_code` | real + age → generalized | Age >89 → "90+" (HIPAA Safe Harbor) |

The first three are healthcare code sets. MCC (Merchant Category Codes) is a financial/merchant set for billing and transaction classification. All are opt-in (not bundled in the wheel). Activate via ETL fetch command or supply your own custom code sets.

## Differential privacy (1 feature)

Marginal differential privacy on generated synthetic data.

- **Marginal DP**: Per-column privacy via OpenDP mechanisms + Google composition. Numeric and categorical columns only. Configured via `global_settings.dp` with epsilon/delta budget and required `column_schema` declarations. Generates rows from a DP-noisy snapshot. Does not cover masked output, dates, free text, or joint distributions.

## Column auto-recognition (STORM) (25)

AI-assisted PII detection. Off by default; advisory only (user confirms all suggestions).

Detects: ssn, npi, mrn, icd10, email, person_name, person_phone, address, us_phone, pan, iban, health_plan_id, member_id, vin, isbn13, ndc, date_of_birth, and others.

## Execution routes (4)

Automatic routing based on data size and memory constraints.

| Route | RAM use | Speed | Best for | Supports |
|---|---|---|---|---|
| **In-memory (pandas)** | Full dataset | Fast | <1 GB | Masking, generation |
| **Polars native** | Full dataset + overhead | Faster | <2 GB, prefer speed | Masking, generation |
| **Sequential** | Per-table chunked | Medium | Medium data (1-10 GB) | Masking, generation, all strategies |
| **Out-of-core (DuckDB)** | Configurable cap | Slower | Large data (10+ GB) | Masking, generation, spills to disk |

The router automatically selects the best route based on available RAM and dataset size.

## Foreign key support

Referential integrity preservation across tables.

- **Mask mode**: Configured orphan policies (drop invalid, remap to valid parent keys)
- **Generate mode**: Parent-before-child compilation; mint foreign key pools from parent keys
- **Fanout**: Configurable distribution (uniform, sequential, weighted, with optional bounds)
- **Supported topologies**: Acyclic generate-to-generate tables only (mask-parent to generate-child is not supported in current version)

## Text processing

- **Pattern detection**: Email, phone, SSN, IP address, credit card patterns
- **Named entity recognition (NER)**: Optional spaCy-backed person name and location detection (requires `[ner]` extra)
- **Free-text strategies**: `text_redact` (replace), `text_mask` (replace with synthetic)

## Determinism and keys

- **Seed-based**: Fixed `global_settings.seed` produces identical output across runs
- **Secret-based masking**: Optional `global_settings.mask_secret_ref` for confidential keying (not used in generation, affects masking only)
- **Determinism modes**: Full reproducibility or output randomness controlled per run

## Validation and safety

- **Fail-closed design**: Configuration errors rejected at compile time, not silently accepted
- **Schema validation**: YAML schema enforcement with descriptive errors
- **Referential integrity checks**: Foreign key cycles, dangling references, and invalid masking topologies detected upfront
- **DP budget enforcement**: Declared epsilon/delta ceilings enforced; compositions computed and checked

## What is not covered

- Masked output carries no privacy guarantee
- Dates and free text are not covered by differential privacy
- Conditional generation (`condition_on`) and joint distributions not covered by DP
- Cross-table joint distributions not modeled
- Composite foreign keys are not sampled tuple-wise (no joint validity)
