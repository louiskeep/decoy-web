## Execution routes

Decoy picks a route automatically from the dataset size and available memory.

| Route | RAM use | Best for |
| --- | --- | --- |
| In-memory (pandas) | Full dataset | &lt;1 GB |
| Polars native | Full dataset plus overhead | &lt;2 GB, prefer speed |
| Sequential | Per-table chunked | 1 to 10 GB |
| Out-of-core (DuckDB) | Configurable cap, spills to disk | 10 GB and up |

## Validation and safety

- Fail-closed: configuration errors are rejected at compile time, not run time.
- Schema validation with descriptive errors.
- Referential-integrity checks: FK cycles, dangling references, and invalid
  masking topologies are caught before any data is written.
- DP budget enforcement: declared epsilon/delta ceilings are checked.

## Limits

See [Security, privacy, and compliance limits](/docs/reference/limits) for what
Decoy does not cover (masked output carries no DP guarantee; DP is per-column
marginals on generated data only; composite FKs are not sampled tuple-wise).
