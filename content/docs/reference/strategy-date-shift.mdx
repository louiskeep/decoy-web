---
title: date_shift
description: Shift dates by a deterministic, bounded offset.
---

The same source date always shifts to the same output date within a namespace, so
the spacing between a row's events is preserved while the absolute dates move. Use
it for HIPAA-style date generalization.

## Settings

Set under `provider_config` on a mask column.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `min_days` | integer | `-365` | Earliest shift, in days |
| `max_days` | integer | `365` | Latest shift, in days |
| `namespace` | string | per-table default | Binds the offset; the same namespace gives the same date the same shift |
| `deterministic` | boolean | `false` | Column-level flag; `date_shift` is keyed, so repeat runs match regardless |

## Examples

```yaml
tables:
  - name: accounts
    columns:
      - name: signup_date
        strategy: date_shift
        namespace: signup_date
        provider_config:
          min_days: -30
          max_days: 30
```

Before and after (same seed, so the mapping is stable):

| Column | Before | After |
| --- | --- | --- |
| `signup_date` | `2023-04-11` | `2023-03-19` |
| `signup_date` | `2022-11-02` | `2022-11-21` |
| `signup_date` | `2024-01-19` | `2024-02-08` |

To anchor every date for one entity to the same offset (so a patient's whole
timeline shifts together), give the date column and the entity key the same
`namespace`.
