## Requirements

- Python 3.10, 3.11, or 3.12.
- A checkout of the `decoy` and `decoy-engine` source, or access to the
  private package index your organization has configured. `decoy` (the CLI)
  depends on `decoy-engine` (the data-plane library); both install together.

<Callout type="info" title="decoy is not on public PyPI yet">
  `pip install decoy` is the install command you will use once Decoy
  reaches general availability. Today, install from source as described
  below.
</Callout>

## Install from source

This is the install path that works right now. From a checkout of
`decoy-engine`, then a checkout of `decoy`, in a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate    # PowerShell: .venv\Scripts\Activate.ps1

pip install -e ./decoy-engine
pip install -e ./decoy
```

If your organization instead publishes `decoy-cli` and `decoy-engine` to an
internal package index, point `pip` (or `uv pip`) at that index and install
`decoy-cli` directly; the console command is the same either way.

The console script is `decoy`, even though the PyPI distribution name is
`decoy-cli` (the import package and CLI stay short; `decoy-cli` on the index
just says plainly what the package is).

## Check the install

Verify the CLI can see its runtime dependencies with `decoy doctor`:

```bash
decoy doctor
```

```
Decoy environment health:

 Check          Kind   Status   Note
 ─────────────────────────────────────
 python         info   pass     3.11.2
 decoy-cli      info   pass     0.1.0
 decoy_engine   hard   pass     0.4.0
 pyarrow        soft   pass     24.0.0
 polars         soft   pass     1.42.0
 lark           soft   pass     1.3.1
 stdnum         soft   pass     2.2

All checks passed.
```

`doctor` exits `0` when every hard requirement is present. A missing hard
requirement (`decoy_engine` itself) is a non-zero exit; missing soft
requirements print a warning but do not fail the check, since each one gates
a specific feature (Arrow/Parquet support, the Polars execution adapter,
derived-column expressions, checksum-based ID validation) rather than the
CLI as a whole. `decoy doctor --json` emits the same report as JSON for CI
or support tooling; `decoy doctor --quiet` runs silently and reports health
only through its exit code.

Confirm the version directly with:

```bash
decoy --version
```

```
decoy 0.1.0
```
